# Наш дом

Маленькое приложение для двух взрослых, которые живут вместе. Устанавливается на экран «Домой» iPhone. Вход по собственной почте и паролю; ChatGPT не требуется.

## Что уже работает

- Общие покупки с отметками «Куплено».
- Общие дела: взять себе, назначить другому при создании или позже, изменить исполнителя, выполнить, вернуть в список. Назначать могут оба участника.
- Светлая, тёмная и системная темы. Быстрое переключение значком в шапке; подробный выбор в «Ещё → Тема оформления». Выбор индивидуален и сохраняется на устройстве.
- Ответ к сегодняшнему ужину и примерное время прихода.
- Одна общая записка «на холодильнике».
- Общие важные записи: контакты и заметки.
- Личные регулярные платежи мамы: сумма, день месяца, отметка оплаты за текущий месяц. При следующем месяце оплаченная отметка не переносится. День 31 в коротком месяце становится последним днём месяца.
- Приглашение второго человека по одноразовой ссылке, привязанной к его почте.
- Смена пароля, выход, восстановление через секрет владельца, выгрузка доступных данных в JSON.
- Обновление общих записей каждые 15 секунд и при возвращении в приложение.

Это учёт платежей, не переводы денег. Push-уведомлений и банковской интеграции в MVP нет. При отсутствии сети приложение не принимает изменения и просит повторить попытку; личные API-данные не кэшируются.

## Запуск на Vercel

1. Размести содержимое этой папки в своём GitHub-репозитории. В Vercel выбери **Add New → Project → Import**. Если загружена вся рабочая папка, выставь **Root Directory: nash-dom**. Если только содержимое архива — оставь корень.
2. **Framework Preset: Other**. Build Command и Output Directory уже заданы в `vercel.json`: `npm run build` и `public`. Node.js 24.x (или поддерживаемая версия >=22.13).
3. В проекте открой **Storage → Connect Database / Marketplace → Neon**. Подключи PostgreSQL-базу к **Production**. Интеграция должна добавить **DATABASE_URL**. Если переменная получила другое имя, скопируй её значение в `DATABASE_URL` внутри настроек Vercel. Не добавляй строку подключения в код или браузер.
4. В **Settings → Environment Variables** добавь **SETUP_KEY** — случайный секрет не короче 24 символов. Сгенерировать локально:

   ```sh
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

   Сохрани его в менеджере паролей. Это ключ первоначальной настройки и аварийного восстановления доступа, не пароль мамы. Не публикуй его и не отправляй с приглашением.

5. Нажми **Deploy / Redeploy** после подключения базы и переменных. Таблицы создаются автоматически на первом запросе. Файл SQLite на Vercel не используется.
6. В **Settings → Environment Variables** задай **APP_ORIGIN** равным адресу приложения, например `https://nash-dom-example.vercel.app` (без завершающего слеша), и сделай Redeploy. Если меняешь домен — обнови переменную.
7. Открой адрес. На первом экране введи `SETUP_KEY`, своё имя, почту и новый пароль от 10 символов. Будет создан первый профиль, без раздела платежей.
8. В **Ещё → Создать приглашение** введи мамину почту. Скопируй ссылку и лично отправь ей. Ссылка действует 7 дней и только один раз; новая ссылка отменяет предыдущую.
9. Мама открывает ссылку на своём телефоне, вводит ту же почту, своё имя и придумывает свой пароль. Ей автоматически назначается профиль с личными оплатами. Письмо приложение само не отправляет, почта здесь служит логином и привязкой приглашения.
10. На обоих iPhone: открыть адрес в Safari → «Поделиться» → «На экран Домой». При наличии переключателя «Открывать как веб-приложение» включить его.

Внешняя защита Vercel, требующая аккаунт Vercel для просмотра сайта, не должна быть включена для вашего рабочего production-адреса: доступ к данным уже проверяет приложение. Если видите сначала страницу входа Vercel — проверьте **Deployment Protection** для выбранного адреса. Не отключайте защиту всего аккаунта.

База и хостинг имеют собственные тарифы; тариф выбирает владелец в Vercel/Neon. Архив кода не подключает оплату автоматически.

## Кто что видит

Роль назначается сервером при создании профиля, пользователь не выбирает её переключателем. Второй профиль может быть только один. Обычный первый профиль не получает список платежей, суммы и историю оплат ни через API, ни в экспорте. Доступ к чужим операциям оплаты возвращает 403.

Как владелец хостинга и базы ты технически сохраняешь административный доступ к данным и секретам. Ограничение платежей действует между обычными профилями приложения, а не против администратора инфраструктуры.

Пароли хранятся в виде salted scrypt-хешей, сессии — в HttpOnly/SameSite cookies и в виде хешей в базе. На HTTPS cookie получает Secure. Регистрация закрыта после создания двух профилей. Запросы изменения проверяют Origin, входы ограничены по частоте. Секреты не попадают в статический код.

Код входа — собственная минимальная реализация для двух человек, без проверки владения почтой через письма. Не используйте его как публичную платформу для регистрации посторонних.

## Локальный просмотр

Нужен Node.js 24.x. В папке проекта:

```sh
npm install
npm run dev
```

Открыть `http://localhost:5173`. Если `DATABASE_URL` не задан, используется локальная SQLite-база `.data/home.sqlite`. Ключ первого входа будет показан только в терминале и меняется при новом запуске, если не задан в `.env.local`.

Для постоянного локального ключа скопируй `.env.example` в `.env.local` и заполни `SETUP_KEY`. Не коммить `.env.local`. Локальная база и рабочая Neon-база — разные. Удаление локальной базы не затрагивает серверные данные.

Тестовые профили, созданные при проверке интерфейса, находятся только в локальной базе. В архив и production они не включены. Если они присутствуют в текущем локальном просмотре: `child@demo.local`, пароль `DemoHousehold2026!`. Это публичные тестовые данные, не использовать в production.

## Проверки

```sh
npm run build
npm test
```

Проверяются создание и приглашение профилей, серверные роли, совместные изменения, захват дел, ужин, закрытость оплат и экспорта, CSRF, выход и отзыв сессий при смене пароля. На Windows с запретом дочерних процессов:

```sh
node --test --test-isolation=none tests/household.test.mjs
```

Локальные проверки используют SQLite. Работа с настоящим Neon и развёртывание на Vercel требуют подключения твоего проекта и базы и отдельно проверяются после публикации.
